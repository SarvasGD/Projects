# 04. Точка старта следующего чата

## Последняя подтверждённая рабочая точка

- Репозиторий и пайплайн GitHub уже настроены; повторно их не настраивать.
- Кодовая база main — v0.3.2.
- Пользователь подтвердил, что overlay полностью заменяет штатный список истории Google; список при этом содержит ложные одноходовые элементы и неполные данные.
- Markdown выбран как единственный формат экспорта; TXT исключён.
- Ключевой дефект текущего кода: detectRows() широко выбирает кликабельные элементы, а describeRow() допускает t:<title> как ключ. Это невалидная классификация, не переносить её в финальную архитектуру.
- Google Search Services History документированно включает поисковые запросы и Generative AI responses AI Mode. Google AI Mode history показывает past searches. Это объясняет появление одноходовых элементов как часть поведения продукта, но точный момент rollout для конкретного аккаунта не установлен.
- Функция фильтра по количеству реплик и удаление из органайзера предложены, но детали UX/апрув ещё не закрыты.

## Первый шаг

**Не менять production-код. Сначала исследовать DOM структуры сообщений.**

1. Прочитать этот handoff package, дорожную карту и текущий content.js v0.3.2.
2. Изучить статью LLMnesia и её сценарий импорта с Resume/retry.
3. Расширить dev-диагностику так, чтобы она снимала анонимизированную структуру не только history row, но и содержимого открытого AI Mode conversation: роли, теги, атрибуты, число message containers и геометрию. Не копировать запросы, ответы, источники или личное содержимое.
4. Получить два DOM-снимка из реального Google AI Mode: одноразовый запрос с одной репликой пользователя и полноценный диалог с 2+ репликами пользователя.
5. Сопоставить реальные признаки и написать тесты на обе категории и неизвестные строки.
6. Только после подтверждения признаков реализовать классификатор, счётчик реплик и фильтр.

## Критерии первого технического результата

- Снимок показывает реальные повторяющиеся контейнеры сообщений и признаки ролей.
- Можно надёжно посчитать сообщения пользователя, не смешивая их с ответами AI, источниками и элементами интерфейса.
- Один запрос не превращается в полноценный чат только по названию или факту присутствия в history.
- Неизвестные элементы остаются не классифицированными; старые папки и индексы не повреждаются.

## Чего не делать на старте

- Не продолжать эвристики по названию/ширине/числу кликабельных строк.
- Не чистить массово локальную базу.
- Не делать серверное удаление чатов, пока identity не прошла браузерную проверку.
- Не просить пользователя вручную синхронизировать локальные записи с Google.
- Не добавлять новые функции, пока не решена классификация.
- Не считать PR #10 или v0.3.2 одобренной финальной реализацией идентификации.
