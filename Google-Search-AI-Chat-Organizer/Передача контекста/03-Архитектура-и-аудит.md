# 03. Архитектура и аудит

## 1. Источник истины и владение данными

**Google — единственный источник истины по составу и состоянию диалогов.**

| Данные | Владелец / источник | Локальная роль |
|---|---|---|
| Наличие диалога | Google AI Mode history | Органайзер отражает актуальное состояние |
| Название и дата/порядок | Google | Кэш для быстрого отображения, обновляемый из Google |
| Стабильный ID / URL | Google DOM / ссылка диалога | Ключ для папочного назначения |
| Папки, подпапки, цвет, порядок | Органайзер | Локальные метаданные пользователя |
| Полнотекстовый индекс | Содержимое открытой/импортированной сессии | Локальный кэш для поиска и Markdown-экспорта |
| Состояние реплик / message count | Содержимое диалога Google | Рассчитываемая метаинформация; обновляется при повторном чтении |

Наличие записи только в chrome.storage.local не означает, что чат существует в Google. Запись, которой больше нет в Google после подтверждённой полной синхронизации, не должна оставаться в активном списке.

## 2. Автоматическая синхронизация

События для синхронизации:

1. При запуске/открытии страницы Google AI Mode.
2. При обнаружении динамического изменения штатной истории через MutationObserver.
3. После действия пользователя в Google (новый диалог, продолжение, переименование, удаление).
4. После действия удаления из органайзера — повторное чтение Google и проверка результата.
5. По команде обновления/повторного сканирования, если пользователь её вызывает.

Алгоритм:

1. Считать штатные строки истории и доступные метаданные.
2. Догрузить список до подтверждённого конца (lazy loading).
3. Классифицировать элементы: полноценный диалог / одиночный запрос / не классифицировано.
4. Сопоставить полноценные диалоги с локальными папочными метаданными по стабильному ID или подтверждённому URL.
5. Добавить новые диалоги; обновить названия и состояние изменённых.
6. Отразить удалённые в Google диалоги в органайзере автоматически. Не требовать от пользователя отдельного локального удаления.
7. Не удалять/не перемещать папочные назначения при временно неполном DOM, ошибке подгрузки или неоднозначном сопоставлении.

**Условия подтверждения удаления:** список полностью загружен; элемент отсутствует в повторных стабильных сканах; нет активной фильтрации/сворачивания/временной подмены DOM. До этого отсутствие строки трактуется как неизвестное состояние, не как доказанное удаление.

## 3. Идентификация и классификация

Иерархия признаков:

1. Стабильный уникальный ID сессии/thread, если реально присутствует.
2. Подтверждённый URL/параметр, однозначно идентифицирующий диалог, а не только поисковый запрос.
3. Структурные признаки открытой AI Mode-сессии и её сообщений.
4. Если тип элемента не доказан — **не классифицировать его как чат**. Не использовать название как самостоятельный ID.

Критически важно различать:
- одноразовый поисковый запрос / одноходовую AI Mode activity;
- многоходовой AI Mode conversation;
- переход из AI Overview в AI Mode, который Google может учитывать отдельными записями Search history;
- не классифицированную строку.

Google официально описывает Search Services History как историю, включающую поисковые запросы и Generative AI responses в AI Mode. Поэтому наличие элемента в Google history само по себе не означает, что это многоходовой чат.

## 4. Счётчик реплик и фильтр

**Основной продуктовый фильтр — число сообщений пользователя (user turns), а не число всех DOM-элементов.**

Предлагаемые статусы расчёта:
- Не рассчитано;
- В процессе;
- Готово: N реплик пользователя;
- Ошибка / повторить.

Предлагаемые фильтры: 1 реплика, 2+ реплики, пользовательский порог N. Точные пресеты и место в интерфейсе — на пользовательский апрув.

Возможные источники числа:
1. Счётчик/метаданные непосредственно в Google DOM строки, если они будут найдены и проверены.
2. Чтение содержимого открытого диалога и подсчёт сообщений с ролью пользователя.
3. Последовательный импорт доступных сессий с прогрессом, сохранением прогресса, Resume и retry — референс LLMnesia.

Не считать количество строк истории числом сообщений. Не считать сообщения AI пользовательскими репликами. Не открывать все диалоги автоматически без отдельного согласования поведения импорта и защиты от вмешательства в активную/незавершённую сессию.

## 5. Удаление из органайзера

**Одна операция над Google, одна последующая синхронизация. Никакого двойного удаления.**

Поток:
1. По точному стабильному ID найти исходную строку Google.
2. Открыть штатное меню More / ⋮ именно этой строки.
3. Выбрать Delete; перед действием показать подтверждение с названием диалога.
4. Повторно просканировать Google.
5. Если Google подтвердил исчезновение строки — она автоматически исчезает из активного органайзера; локальная связка папки синхронизируется по политике удаления.
6. Если сопоставление не однозначное или DOM-контрол не распознан — отключить удаление для этой строки, не угадывать.

Риск:
- по title — высокий и недопустимый;
- по нестабильному URL — средний;
- по проверенному уникальному thread ID и подтверждённой native row — низкий/управляемый, но остаётся риск изменения DOM Google.

Удаление из AI Mode history и Search Services History/My Activity может иметь разные эффекты. Google указывает, что удалённый AI Mode search может оставаться в My Activity менее 24 часов; при переходе из AI Overview в AI Mode могут существовать две связанные Search history entries.

## 6. Роли модулей

| Модуль | Ответственность |
|---|---|
| Google DOM adapter | Читать native history rows, открытые беседы, сообщения, действия меню |
| Conversation classifier | Отличать полноценные диалоги от одиночной activity и неизвестных строк |
| Thread identity | Стабильный ключ, сопоставление и защита от коллизий |
| History synchronizer | Сверять Google и локальные метаданные автоматически |
| Folder organizer | Дерево папок, перемещение, цвет и порядок |
| Conversation importer/indexer | Чтение текста, подсчёт пользовательских реплик, прогресс/Resume/retry |
| Search/export | Поиск по названию и содержимому; Markdown export |
| Google action adapter | Нативное удаление и проверка результата |
| Diagnostics/test harness | Анонимизированный DOM snapshot, unit/jsdom и браузерная приёмка |

## 7. Критические правила аудита

- Не создавать полноценный чат из кликабельной строки без подтверждённой идентичности/классификации.
- Не объединять разные диалоги по общему q или заголовку.
- Не удалять папки/индекс из-за неполной загрузки истории.
- Не выдавать локальный кэш за текущую серверную историю.
- Не считать jsdom проверкой реального Google интерфейса.
- Не требовать от пользователя двойного удаления или ручной синхронизации.
