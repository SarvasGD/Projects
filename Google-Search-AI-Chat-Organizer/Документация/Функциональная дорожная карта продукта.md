# Функциональная дорожная карта продукта
**Google Search AI Chat Organizer**

**Актуальность:** 23.11.2026  
**Версия разработки:** v0.4.0 (ветка прототипа; ещё не слита в main)  
**Основная кодовая база main:** v0.3.2

## Текущая стадия продукта

**ТЕКУЩАЯ СТАДИЯ: ПРОТОТИП — В РАЗРАБОТКЕ**

**Prototype Gate не пройден. MVP ещё не начат.**

Уже есть работающий UI-прототип: overlay заменяет штатный блок истории Google при наличии подтверждённой identity; дерево папок, поиск и Markdown-экспорт присутствуют в коде. Полное замещение штатного списка подтверждено пользователем в v0.3.1; v0.4.0 дополнительно проверен в Chromium на synthetic fixtures. Если стабильных identity нет совсем, fail-open оставляет нативную историю доступной.

Но главный риск продукта — правильная идентификация именно полноценных AI Mode-диалогов — не закрыт. v0.4.0 уже прошёл автоматические проверки на синтетическом DOM, однако реальная разметка Google для thread ID, одиночных запросов и нескольких реплик ещё не подтверждена.

### Что не хватает до Prototype Gate

| Критерий прототипа | Текущее состояние |
|---|---|
| Google AI Mode scope отделён от обычной поисковой выдачи | ✅ Реализовано в v0.4.0: только Google /search с udm=50; автотест есть |
| Title-only identity исключён | ✅ Реализовано: без стабильного ID/thread URL строка остаётся неклассифицированной |
| Стабильный ключ диалога не зависит от текста q | ✅ Реализовано: thread key строится по identity-параметрам; migration нормализует старые URL |
| Неклассифицированные строки не попадают в список чатов и не удаляются ошибочно | ✅ Реализовано и покрыто тестами |
| Синхронизация удалений безопасна при полной загрузке | ✅ Протестировано на synthetic DOM; реальный Google DOM ещё не подтверждён |
| Подсчёт именно реплик пользователя | 🧪 Есть диагностический счётчик по явным role markers; неизвестно, какие маркеры реально использует Google |
| Реальные DOM fixtures одноходовой и многоходовой сессии | ⚪ Не получены |
| Реальная классификация Google history по этим fixtures | ⚪ Не завершена |
| Overlay v0.4.0 на целевой странице AI Mode | 🧪 Синтетические проверки пройдены; реальный регрессионный прогон ещё не выполнялся |

**Почему это ещё не MVP:** MVP должен уже надёжно решать основную пользовательскую задачу. Пока не подтверждено, что расширение видит все настоящие диалоги, исключает одноразовые AI-запросы и правильно считает реплики. Без этого папки и фильтры будут организовывать неверный набор объектов.

## Как читать дорожную карту

В таблице используются три независимых измерения.

### 1. Решение пользователя — апрув

| Маркер | Значение |
|---|---|
| ✅ Одобрено | Пользователь прямо подтвердил требование или решение. |
| 🟡 На апрув | Предложение сформулировано, но окончательно пользователем не утверждено. |
| ⛔ Отклонено | Пользователь отверг подход; не реализовывать. |

### 2. Фактический статус разработки

| Маркер | Значение |
|---|---|
| ⚪ Не начато | Работа над функцией ещё не велась. |
| 🗓 Запланировано | Функция одобрена, включена в согласованный объём и поставлена в очередь, но активная реализация не началась. |
| 🔄 В работе | Идёт реализация или существенная доработка. |
| 🧪 Автотесты пройдены | Автоматические тесты пройдены; реальное поведение Google ещё не доказано. |
| 🖥 Проверено в браузере | Реальная браузерная работа проверена на целевом сайте. |
| ✅ Готово | Критерий приёмки выполнен; функция пригодна к использованию на соответствующем этапе. |
| ⛔ Заблокировано | Есть конкретная зависимость, без которой двигаться дальше нельзя. |

«Не начато» и «Запланировано» различаются: у запланированной функции уже одобрены scope и приоритет, у не начатой — нет активной работы и ещё не наступила очередь.

### 3. Целевой этап первой поставки

Маркер **◆** в одной колонке стадии означает только то, что к этому этапу функция впервые должна достичь своего критерия готовности. Это не прогресс и не технический статус.

## Этапы продукта и критерии перехода

| Этап | Для чего нужен | Что должно быть получено на выходе | Условие перехода |
|---|---|---|---|
| **Прототип** | Снять главные технические риски до сборки полного продукта. | Доказана структура Google AI Mode; есть надёжная identity; различаются одиночные и многоходовые сессии; считаются user turns; подтверждены overlay, lazy loading и безопасная синхронизация. | Prototype Gate: реальные DOM fixtures и тесты подтверждают классификацию, identity и счётчик; неизвестные строки не становятся чатами; данные не теряются. |
| **MVP** | Дать минимально полезный законченный органайзер для ежедневного использования. | Полный список подтверждённых диалогов; авто-синхронизация; фильтр реплик; папки до 4 уровней; перемещение; поиск; Markdown; сохранение локальных метаданных. | MVP Gate: основной сценарий работает сквозным образом; все P0-критерии закрыты; CI и интеграционные тесты не выявляют дублей, ложных удалений или потерь папок. |
| **Закрытая бета** | Проверить уже собранный MVP на ограниченном числе реальных аккаунтов и браузеров. | Устойчивость к вариациям Google DOM; нативное удаление; импорт с прогрессом/Resume/retry; восстановление после ошибок. | Критические сценарии проходят внутренние тесты и ограниченную реальную проверку; нет потери данных и опасных ошибок удаления. |
| **Soft Launch** | Ограниченно открыть продукт более широкой аудитории. | Упакованная сборка, onboarding, документация, производительность на больших историях, совместимость и процесс поддержки. | Установка и обновление понятны; эксплуатационные риски приемлемы. |
| **Public Launch** | Публичный выпуск и долговременное сопровождение. | Публичная документация, релизная сборка, политика конфиденциальности, канал обратной связи, процесс исправления изменений Google. | Продукт доступен широкой аудитории, определены сопровождение и релизный цикл. |

**MVP и закрытая бета — не два конкурирующих этапа разработки.** MVP — минимальный функциональный объём продукта; закрытая бета — ограниченный способ выпуска и проверки уже собранного MVP. Поэтому закрытая бета следует после MVP.

### Что считать готовностью каждой строки

- **Готово к прототипу** — главная техническая гипотеза проверена на реальном DOM и закреплена воспроизводимыми tests/fixtures.
- **Готово к MVP** — пользовательская функция интегрирована в сквозной сценарий и покрыта регрессионными тестами.
- **Готово к закрытой бете** — функция выдерживает реальные аккаунты, несколько браузеров и ошибки/повторы; опасные действия защищены.
- **Готово к Soft Launch** — продукт можно устанавливать и обновлять без участия разработчика; основные эксплуатационные риски закрыты.
- **Готово к Public Launch** — есть документация, политика конфиденциальности, поддержка и план сопровождения.

## Правило тестирования

Разработчик сначала выполняет максимум проверок самостоятельно:
1. syntax / manifest / permissions;
2. unit tests ключей, классификатора, message count и миграции;
3. DOM fixtures и Playwright/Chromium;
4. integration-тесты lazy loading, MutationObserver, overlay и sync;
5. data regression — отсутствие дублей, потери индекса и folder bindings.

Пользователь участвует только на крупных вехах: Prototype Gate, MVP Gate, Closed Beta. Не просить проверять отдельные CSS-изменения, кнопки, промежуточные PR или каждый алгоритм.
