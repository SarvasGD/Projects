**Google Search AI Chat Organizer**

**Актуальность:** 26.11.2026  
**Версия-кандидат:** v0.4.1  
**ТЕКУЩАЯ СТАДИЯ ПРОЕКТА: ТЕХНИЧЕСКИЙ ПРОТОТИП v0.4.1; Prototype Gate частично закрыт.**  
**Сроки:** календарная оценка после Prototype Gate. До этого даты не назначаются.

## 1. Где находится проект и почему это ещё не MVP

v0.4.1 реализует строгую identity, отказ от title-only fallback, подсчёт реплик открытой сессии, фильтрацию и обработку виртуализированной истории. Реальный снимок Google от 26.11.2026 подтвердил 20/20 строк с `data-thread-id` на вложенных кнопках и структуру `div[role=listitem]`. Автоматические DOM/Playwright тесты проверяют и эту разметку.

Не подтверждены только реальные user/assistant markers и подсчёт реплик в открытой сессии; для них нужен один snapshot на живом многоходовом диалоге. Полный importer истории с progress/Resume/retry и полный sync по всему аккаунту не относятся к прототипу — это объём MVP. Поэтому v0.4.1 остаётся **техническим прототипом**, а не MVP.

| Критерий текущей стадии | Результат | Что осталось |
|---|---|---|
| Строгая identity вместо названия | 🖥 Живой DOM подтверждён | Google history: 20/20 строк имеют `data-thread-id` на вложенной кнопке внутри `div[role=listitem]`; v0.4.1 адаптирован к этой структуре и покрыт регрессией |
| Исключение q-only и generic clickable rows | 🧪 Автотесты пройдены | Текущий снимок истории содержит 20 подтверждённых thread rows; q-only остаётся покрыт отдельным fixture, так как в live-снимке таких строк нет |
| Подсчёт user turns | 🧪 На fixtures пройдено | Один live snapshot открытой многоходовой сессии: подтвердить user/assistant markers и сверить count |
| Безопасный fallback к Google | 🧪 Playwright + DOM regression пройдены | Один live контроль v0.4.1 после обновления расширения; убедиться, что unknown/partial возвращает native Google list |
| Сканирование/lazy loading | 🧪 Виртуализированные страницы покрыты тестами; в v0.3.2 список был полностью загружен | Один контрольный прогон нового сканера v0.4.1 на истории пользователя |
| Синхронизация изменений истории | 🧪 Add/rename/delete проверены на fixtures; live row identity подтверждена | Проверить динамические add/rename/delete на v0.4.1; полный importer и reconciliation всей истории относятся к MVP |
| Воспроизводимые проверки | ✅ 26/26 jsdom + Playwright Chromium; post-merge CI passed | По мере новых найденных вариантов Google DOM пополнять regressions |

## 2. Что означают стадии проекта

Это последовательность стадий с отдельными контрольными воротами (Stage-Gate). В конце каждой стадии проверяются deliverables и заранее заданные критерии; результатом становится Go, Hold или Rework. Стадия меняется только после прохождения Gate.

Источники модели:
- Stage-Gate International: https://www.stage-gate.com/about/stage-gate-innovation-performance-framework/discovery-to-launch-process/
- DOE Stage-Gate: https://www.energy.gov/sites/prod/files/2015/05/f22/itp_stage_gate_overview.pdf

| Стадия | Назначение | Что входит в результат | Gate перехода |
|---|---|---|---|
| **Прототип** | Доказать техническую реализуемость самых рискованных частей. | Надёжная identity, различение одноходовой activity и диалога, подсчёт user turns, безопасный overlay/fallback, fixtures и автотесты. | Реальный Google DOM подтверждён; один запрос не становится чатом; счётчик проверен на живой сессии; неизвестные строки не блокируют Google; тесты проходят. |
| **MVP** | Минимально законченный продукт, который уже решает основную пользовательскую задачу целиком. | Полная доступная история, импорт и count всех сессий, фильтр реплик, автоматическая синхронизация, папки/перемещение, поиск, Markdown, сохранение пользовательской организации. | Сквозной сценарий от импорта истории до организации/поиска/экспорта работает; закрыты P0; нет известных ложных чатов, дублей и потери папок. |
| **Закрытая бета** | Проверить готовый MVP на ограниченной группе реальных аккаунтов. | Устойчивость к вариантам Google DOM, retry/Resume, восстановление, безопасное нативное удаление, большие истории, совместимость браузеров. | Нет критических ошибок identity/sync/data loss; удаление работает только по точному ID; поддерживаемые браузеры проходят общий набор. |
| **Soft Launch** | Ограниченный выпуск более широкой аудитории. | Упаковка, установка/обновление, onboarding, документация, производительность и поддержка. | Установка и обновление воспроизводимы без разработчика; поддержка и восстановление готовы. |
| **Public Launch** | Публичный релиз и сопровождение. | Публичная сборка, документация, приватность, обратная связь и процесс реакции на изменения Google. | Публичный релиз готов, назначен процесс сопровождения. |

**MVP предшествует закрытой бете:** MVP — это функциональная полнота продукта; Closed Beta — ограниченный способ выпуска и проверки уже готового MVP. Это разные измерения.

Microsoft описывает MVP как работающую версию, которая даёт реальную пользу пользователям, а не черновик или чек-лист функций: https://www.microsoft.com/en-us/startups/minimum-viable-product-mvp

## 3. Две независимые характеристики функции

**Решение пользователя** и **техническое состояние** — разные поля.

| Решение пользователя | Значение |
|---|---|
| ✅ Одобрено | Пользователь прямо подтвердил требование |
| 🟡 На апрув | Предложение ещё не подтверждено окончательно |
| ⛔ Отклонено | Пользователь отверг подход |

| Техническое состояние | Значение |
|---|---|
| ⚪ Не начато | Реализация не выполнялась |
| 🔧 В работе / исправление | Реализация начата или известен дефект |
| 🧪 Автотесты пройдены | Проверено на fixtures; отдельные live DOM-пункты могут оставаться открыты |
| 🖥 Проверено в браузере | Воспроизведено на реальном интерфейсе |
| ✅ Готово | Критерий приёмки выполнен |

У каждой функции один целевой этап первой готовности. Нет повторяющихся точек по стадиям, которые смешивают «не начато» и «запланировано».

## 5. Что конкретно делает MVP

MVP — это законченный пользовательский сценарий:
1. Полная доступная история настоящих AI Mode-диалогов, без одноразовых поисковых активностей.
2. Число реплик пользователя рассчитано для доступных сессий, не только для вручную открытой.
3. Фильтр по числу реплик убирает одноходовые запросы из основного списка.
4. Внешние добавления, переименования и удаления в Google отражаются автоматически.
5. Папки до 4 уровней, перемещение без открытия диалога.
6. Поиск по названию и содержимому, Markdown export.
7. Папки/индексы сохраняются; partial load не трактуется как удаление.

Пока не закрыты пункты 1–4 на полной истории и не подтверждены на live Google DOM, MVP Gate не пройден.

## 6. Политика тестирования

| Уровень | Проверки | Исполнитель |
|---|---|---|
| Статика | Manifest, syntax, permissions, scripts | CI |
| Unit | ID/URL, classifier, count, filters, migrations | Автоматически |
| DOM fixtures | Одноходовые/многоходовые сессии, ответы AI, sources | Автоматически |
| Integration | Lazy loading, MutationObserver, overlay, sync, restore | Playwright после создания harness |
| Data regression | Дубли, потери индекса, folder bindings, ложные удаления | Автоматически |
| Реальный аккаунт | Только то, что нельзя доказать fixtures | Один сводный Prototype Gate |
| Полный сценарий | MVP и Closed Beta | Один сводный приёмочный прогон на веху |

Пользователь не тестирует каждый CSS-патч, кнопку, commit или PR. Сначала разработчик воспроизводит дефект, добавляет fixture, исправляет и прогоняет весь suite.

## Текущая контрольная точка v0.4.1
