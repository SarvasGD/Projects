# Функциональная дорожная карта продукта
**Google Search AI Chat Organizer**

**Актуальность:** 23.11.2026  
**Кодовая база:** main, v0.3.2  
**Текущая стадия:** Прототип. Технический gate идентификации полноценных AI Mode-диалогов ещё не пройден.

## Два независимых статуса

**Решение пользователя — согласована ли функция?**

| Маркер | Значение |
|---|---|
| ✅ Одобрено | Пользователь прямо подтвердил требование. |
| 🟡 На апрув | Предложение сформулировано, но не подтверждено окончательно. |
| ⛔ Отклонено | Пользователь отверг подход; не реализовывать. |

**Техническая готовность — что сделано в коде?**

| Маркер | Значение |
|---|---|
| ⚪ Не начато | Реализация не выполнялась. |
| 🔧 Требует разработки / исправления | Нужен код или исправление известного дефекта. |
| 🧪 Автотесты | Проверено автоматически на тестовых DOM/данных; реальное поведение Google ещё не доказано. |
| 🖥 Внутренне проверено в браузере | Воспроизведено разработчиком в реальном браузере. |
| 👤 Приёмка на контрольной точке | Внутренние проверки завершены; ожидается целевая проверка крупной вехи пользователем. |
| ✅ Принято | Функция прошла требуемую проверку и принята. |

«На апрув» и «требует технического исправления» не конкурируют: первое — статус решения, второе — состояние реализации. Одобренная функция может требовать исправления.

### Почему MVP перед закрытой бетой

**MVP — это объём и функциональная полнота продукта. Закрытая бета — способ ограниченного выпуска и проверки уже собранного MVP.** Сначала создаётся минимально полезная версия, затем её проверяют на ограниченном числе реальных аккаунтов. Soft Launch идёт после закрытой беты: аудитория шире, продукт достаточно стабилен для ограниченного публичного распространения.

## Сроки

Календарные даты пока не назначаются. Оценка будет сделана после прототипного gate, когда станут известны реальные DOM-признаки, способ подсчёта реплик, объём импортера и сложность синхронизации. Затем фиксируются оценки по задачам и контрольные даты MVP/беты.

## Правила продукта

1. Google — источник истины по существованию, названию и состоянию диалогов.
2. Изменения в Google автоматически отражаются в органайзере.
3. Локально хранятся папки, цвета, порядок, UI-настройки и индекс текста; локальный кэш не создаёт отдельную историю чатов.
4. Заголовок и кликабельность не доказывают, что запись является полноценным диалогом.
5. Считать только реплики пользователя, а не все сообщения/DOM-элементы.
6. Удаление из органайзера выполняется через Google; второй локальной операции нет.
7. Не скрывать штатный список до полной подгрузки и успешного позиционирования overlay.
8. CI/jsdom не заменяет тесты на реальных DOM fixtures.

## Политика тестирования: сначала разработчик

| Уровень | Проверки | Кто выполняет |
|---|---|---|
| Статика | Syntax, Manifest V3, permissions, scripts | CI |
| Unit | ID/URL, классификация, счётчик, фильтры, миграции | Автоматически |
| DOM fixtures | Одиночные/многоходовые сессии, варианты Google DOM | Автоматически после получения эталонных fixtures |
| Integration | Lazy loading, MutationObserver, overlay, sync, restore | Playwright/Chromium на fixtures |
| Data regression | Нет дублей, потери индекса, смены folder binding или ложного удаления | Автоматически |
| Реальная браузерная приёмка | Только свойства, недоступные в тестовом harness | Пользователь — на крупных вехах |

Не просить пользователя проверять каждый CSS-патч, кнопку, PR или мелкий алгоритм. Сначала разработчик воспроизводит дефект, создаёт fixture и регрессионный тест, исправляет код и запускает полный набор. Пользователь подключается на Prototype gate, MVP gate и перед Closed Beta либо когда необходим факт только из реального аккаунта.
