## Первый необходимый внешний артефакт

Нынешняя диагностика уже умеет снимать:
- структуру строки истории и её предков;
- имена атрибутов, типы элементов и геометрию;
- структуру контейнеров сообщений;
- явно определяемые роли user/assistant и количество таких узлов;
- только длину текста, без самого содержимого.

Она не раскрывает заголовки, query values, ID-значения или текст переписки. Этого достаточно, чтобы получить один сравнимый пакет для одиночной и многоходовой сессии. После его получения fixtures и вся последующая проверка автоматизируются.

## Критерии перехода

### Prototype Gate
- Реальные fixtures отличают одноходовую activity, многоходовой диалог и неизвестную запись.
- Найден стабильный ключ диалога или доказано, когда Google его не отдаёт.
- User turns считаются отдельно от AI replies.
- Полный список и безопасная синхронизация проходят fixtures без потерь.
- Неизвестные строки не попадают в подтверждённые чаты.
- Overlay не скрывает штатную историю при неполной загрузке/ошибках.

### MVP Gate
- Подтверждённый список, фильтр по репликам, автоматический sync, папки/перемещение, поиск и Markdown работают как единый законченный пользовательский сценарий.
- Нет P0-дефектов, дубликатов и ложных удалений на тестовом наборе.

### Closed Beta Gate
- Импорт/Resume/retry, native delete, восстановление и браузерная матрица проверены на крайних сценариях и ограниченном числе аккаунтов.

## Правило
Не менять production-эвристику наугад. Каждый обнаруженный дефект сначала закрепляется регрессионным тестом, исправляется и проходит весь автоматический набор. Пользователь подключается только для фактов из реального аккаунта и крупных контрольных точек.


## Fail-open поведение

Если после полной подгрузки истории нет ни одной строки с подтверждённой стабильной identity:
- не скрывать штатный список Google;
- не открывать большую панель поверх исходной истории;
- показывать только компактную свёрнутую панель органайзера с объяснением, почему он пока не может заменить историю;
- не создавать активные чат-записи и не выполнять destructive sync.

Если есть хотя бы один подтверждённый диалог и список полностью подгружен, overlay может заменить историю, а неизвестные строки остаются отдельной группой.
