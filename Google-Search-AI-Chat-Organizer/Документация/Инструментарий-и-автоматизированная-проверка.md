## Что проверяют автоматические тесты

- Обычная Google Search не монтирует органайзер и не запускает capture.
- Диалог требует стабильного thread/session ID или identity URL; q/udm alone недостаточно.
- Изменение поисковой формулировки не меняет thread key, если сохраняется mtid.
- Строки без стабильной identity остаются в «Не классифицировано» и не сохраняются как чаты.
- Одинаковые названия не переносят индекс или папку между разными ID.
- Внешнее удаление стабильного чата отражается автоматически после полной verified sync.
- Наличие неизвестных строк блокирует destructive reconciliation.
- Подсчёт user turns отделён от assistant replies, когда role markers явно присутствуют.
- Снимок DOM не передаёт текст сообщений.
- Overlay, lazy loading, migration, folder binding, click proxy и teardown остаются покрытыми smoke tests.

## Ограничение message-role detection

Счётчик v0.4.0 считает только узлы с явными и распознанными атрибутами/ролями. Если Google использует другие маркеры, он вернёт «не определено», а не угадает число. Это намеренное безопасное поведение до получения реальной разметки Google.

## Developer-first тестирование

**Пользователь не тестирует каждый мелкий патч.**

| Проверка | Исполнитель |
|---|---|
| Syntax, Manifest V3, permissions, scripts | CI |
| ID normalization, thread identity, classifier, user-turn count | Unit tests |
| Одиночная/многоходовая сессия, AI replies, sources, unknown rows | DOM fixtures |
| Overlay, scroll, SPA navigation, MutationObserver | Playwright/Chromium fixtures |
| Sync add/rename/delete, partial loading, migration, folder bindings | Integration + regression tests |
| Реальная Google-история, account-specific actions | Один объединённый контроль на Prototype Gate / MVP / Closed Beta |

Сначала разработчик воспроизводит дефект на fixture, создаёт регрессионный тест, исправляет код и запускает полный набор. К пользователю обращаемся только для реальной DOM-структуры/аккаунтного поведения и крупных контрольных приёмок.


## Playwright Chromium integration suite

Файлы:
- \`playwright.config.js\`
- \`tests/e2e/organizer.spec.js\`

Расширение загружается в persistent Chromium context как Manifest V3 extension. Тесты используют локальные Google-подобные HTML fixtures на origin \`www.google.com\`; реальный Google-аккаунт и сеть Google не используются.

Проверяются:
1. Overlay на AI Mode fixture, ожидаемая геометрия и скрытие native list после окончания lazy loading.
2. Раздельное отображение подтверждённой и неклассифицированной строки.
3. Проксирование клика на исходную строку Google.
4. Восстановление native history при сворачивании.
5. Обычная Google Search: расширение не монтируется и не скрывает историю.
6. Unknown-only history: fail-open оставляет native history видимой и не создаёт активных чатов.

Последний полностью зелёный CI run: https://github.com/SarvasGD/Projects/actions/runs/45164482788

**Ограничение:** Playwright подтверждает работу расширения в Chromium engine на synthetic DOM. Он не доказывает, что атрибуты и структура текущего Google AI Mode совпадают с fixture. Это остаётся внешним входом для Prototype Gate.


## Сохранение счётчика реплик пользователя

В v0.4.0 при открытии сессии:
- inspectConversationMessages() считает только явные role markers user / human;
- captureCurrentPage() сохраняет userTurns, userTurnsSource и userTurnsUpdatedAt в соответствующую запись только при стабильной identity;
- при новом пользовательском сообщении count обновляется;
- если маркеры не распознаны, счётчик остаётся null, не подменяется нулём.

Это пока count открытой сессии, а не полный импорт всех старых разговоров. Автоматический импорт с Resume/retry — отдельная задача MVP/закрытой беты.
