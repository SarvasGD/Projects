## 2. Инструменты
| Инструмент | Применение |
|---|---|
| MutationObserver | Следить за изменениями Google DOM и запускать повторную синхронизацию. |
| Scroll metrics | Отслеживать lazy loading; не считать отсутствие новых строк доказанным концом истории. |
| chrome.storage.local | Папки, UI-настройки, локальный индекс; не источник истины о наличии чата. |
| jsdom | Быстрые unit/DOM тесты без аккаунта Google. |
| Playwright/Chromium fixtures | Интеграционные тесты overlay, scroll, menu и sync на сохранённом DOM. |
| Обезличенные DOM snapshots | Воспроизводимые fixtures вариантов истории и conversation DOM. |
| LLMnesia | Референс импорта с Resume/retry; не готовая система папок. |

## 3. Эталонные fixtures
Подготовить обезличенные HTML fixtures:
1. Одноходовая AI Mode-сессия — одна реплика пользователя.
2. Многоходовый диалог — 2+ реплики пользователя.
3. Ответы AI, источники и карточки без дополнительных user turns.
4. Одинаковые названия у разных сессий.
5. AI Overview / обычный Search, не являющийся многоходовым диалогом.
6. Строка history без доступного URL/ID.
7. Частичная загрузка и lazy loading.
8. Вариации DOM Google по доменам/аккаунтам.

Сохранять роли, теги, data-атрибуты и геометрию; заменить все тексты и персональные данные.

## 4. Developer-first testing
**Каждый мелкий патч сначала полностью проверяет разработчик.**

| Уровень | Проверки | Исполнитель |
|---|---|---|
| Статика | Syntax, Manifest V3, permissions, scripts | CI |
| Unit | ID/URL, classifier, count, filters, migrations | Автоматически |
| DOM fixtures | Одноходовые/многоходовые сессии, варианты Google DOM | Автоматически |
| Integration | Lazy loading, MutationObserver, overlay, sync, restore | Playwright/Chromium на fixtures |
| Data regression | Дубли, потери индекса, folder bindings, ложные удаления | Автоматически |
| Account-specific | Серверные side effects, реальное удаление и синхронизация | Один крупный контроль перед бета-этапом |

До обращения к пользователю разработчик должен воспроизвести дефект, создать fixture и регрессионный тест, исправить код и прогнать весь набор. Не просить пользователя проверять каждый CSS-патч, кнопку, PR или мелкий алгоритм.

Пользователь участвует на крупных вехах: Prototype gate, MVP gate, Closed Beta acceptance — либо когда требуется факт, доступный только из реального аккаунта.

## 5. Команды
Из папки Google-Search-AI-Chat-Organizer:

    node --check content.js
    npm test

Будущий Playwright harness запускается в CI на сохранённых fixtures; реальные учётные данные пользователя не требуются для каждого UI-патча.
