# Архитектура данных и автоматической синхронизации
**Актуальность:** 23.11.2026

## 1. Владение данными
**Google AI Mode history — источник истины о составе и состоянии диалогов.**

| Данные | Источник истины | Роль локального хранилища |
|---|---|---|
| Существование диалога | Google | Последнее синхронизированное состояние |
| Название и порядок | Google | Обновляемый кэш |
| Thread/session ID и URL | Google DOM / ссылка | Стабильный ключ для папки |
| Папки, подпапки, цвет, порядок | Органайзер | Локальные пользовательские метаданные |
| Число реплик пользователя | Содержимое сессии Google | Вычисленный кэшируемый счётчик |
| Полнотекстовый индекс | Содержимое сессии | Локальный кэш для поиска и Markdown |

Локальная запись не делает диалог существующим. Добавление, переименование и удаление в Google автоматически отражается в органайзере.

## 2. Автоматическая синхронизация

### Триггеры
- Загрузка Google AI Mode.
- Изменения штатной истории через MutationObserver.
- Возврат фокуса на вкладку и завершение SPA-навигации.
- Завершение действий пользователя в Google.
- Периодическая лёгкая проверка активной вкладки, если Google не генерирует DOM-событие.
- Ручное обновление — только дополнительный инструмент диагностики, не основной workflow.

### Цикл
1. Считать строки истории, ID/URL и признаки типа.
2. Догрузить штатный список до достоверного конца.
3. Классифицировать: полноценный диалог / одноходовая activity / неопределённая строка.
4. Сопоставить подтверждённые диалоги с папочными метаданными по стабильному ID, затем подтверждённому URL.
5. Добавить новые диалоги; обновить название, порядок и count; сохранить папочные связи.
6. Удаление фиксировать только после полной загрузки и повторной стабильной проверки.
7. Неполная загрузка/ошибка не вызывает очистки или перепривязки по одному совпавшему названию.

### Состояния
Не начата → Сканирование → Подгрузка → Сверка ID/URL → Обновление метаданных → Завершена.  
При ошибке — Неполная/Ошибка; destructive reconciliation не выполняется.

## 3. Идентификация и классификация
1. Уникальный thread/session/conversation ID, подтверждённый в реальном DOM/URL.
2. URL, который однозначно указывает на диалог, а не просто на поисковый запрос.
3. Структура открытой сессии и message containers с role markers.
4. Если тип/ID не доказаны — строка остаётся неопределённой.

Не использовать название как самостоятельный ключ. Не объединять чаты по общему q, заголовку или первому сообщению.

## 4. Подсчёт реплик пользователя
Считать только сообщения с ролью пользователя. Ответы AI, источники, карточки, кнопки, заголовки и навигация не являются user turns.

Источники count:
- Достоверные данные Google в history row, если они найдены и проверены.
- Анализ сообщений внутри открытого диалога.
- Последовательный importer, если строка истории не содержит count.

Предлагаемые режимы: 1, 2+, 3+, пользовательский порог N — после апрува UX. Пока count не рассчитан, не выдавать запись за подтверждённый многоходовый диалог.

## 5. Удаление из органайзера
**Одна операция над Google, затем одна автоматическая синхронизация.**
1. По уникальному ID найти точную native row.
2. Открыть штатное меню строки.
3. Показать подтверждение с названием.
4. Вызвать штатный Delete Google.
5. Повторно синхронизировать; после подтверждённого удаления запись исчезает из активного органайзера автоматически.

Если ID неоднозначен — удаление недоступно. Второй шаг «удалить локально» не вводить.

## 6. Автотесты
- Полная/частичная загрузка и временно скрытая история.
- Внешнее добавление, переименование, продолжение и удаление.
- Разные диалоги с одинаковым названием/первым запросом.
- Изменение URL при сохранении thread ID.
- SPA-переход и повторное сканирование.
- Папочная связь после миграции.
- Запрет destructive sync при ошибке/тайм-ауте.
- Нативное удаление и повторная сверка на синтетическом UI.
