# Архитектура данных и автоматической синхронизации
**Актуальность:** 25.11.2026 · **Код-кандидат:** v0.4.1

## 1. Источник истины
**Google AI Mode history — единственный источник истины по наличию, названию и состоянию диалогов.**

| Данные | Источник истины | Локальная роль |
|---|---|---|
| Существование диалога | Google | Последнее синхронизированное состояние |
| Название, порядок, доступность | Google | Обновляемый кэш |
| Thread/session ID и URL | Google DOM / ссылка | Стабильный ключ папки |
| Папки, подпапки, цвет, порядок | Органайзер | Локальные метаданные |
| Число реплик пользователя | Содержимое сессии | Вычисленный кэшируемый счётчик |
| Полнотекстовый индекс | Содержимое сессии | Локальный индекс для поиска/Markdown |

Локальная запись не создаёт диалог. Изменения Google автоматически отражаются при следующей синхронизации.

## 2. Идентификация v0.4.1
1. Явный thread/session/conversation ID в атрибутах строки или содержимого сессии.
2. URL identity с mtid/thread/thread_id/hash thread, если он указывает на отдельную сессию.
3. Если стабильного ID нет — строка остаётся unknown.

Не использовать q + udm без thread identity, название как самостоятельный ключ или произвольную кликабельность как доказательство разговора.

v0.4.1 допускает только явные identity-атрибуты и ссылки. Title-only key не создаётся. Старые title-only записи не удаляются автоматически, но скрываются из active list и не перепривязываются по названию.

## 3. Классификация и user-turn count
Типы: одноходовая AI activity; многоходовой диалог; unknown/not calculated.

Считать реплики пользователя, не ответы AI:
1. Приоритет — явные user-role markers.
2. Transcript fallback — You said / Вы сказали только внутри AI Mode Conversation.
3. Иначе count=null, classification=unknown.

В v0.4.1 счётчик обновляется для открытой/прочитанной стабильной сессии. Для всей истории он пока не рассчитан: full importer с Resume/retry ещё не реализован.

## 4. Автоматическая синхронизация
Триггеры: загрузка AI Mode, MutationObserver, SPA navigation, возврат фокуса, периодическая проверка активной вкладки, завершение действий пользователя.

Цикл:
1. Считать native history rows, ID/URL и structural markers.
2. Догрузить список до доказанного конца.
3. Разделить confirmed stable-ID rows и unknown.
4. Сопоставить подтверждённые диалоги с папками только по stable ID или доказанному URL.
5. Добавить новые; обновить название/состояние; сохранить folder bindings.
6. Удаление признавать только после полной загрузки и повторной стабильной сверки.
7. При incomplete scan или unknown rows не помечать старые записи удалёнными и не скрывать Google history.

v0.4.1 выполняет DOM rescans и базовую reconciliation. Add/rename/delete покрыты jsdom/Chromium fixtures. Удаление из local cache и папочных связей подтверждается только после двух полных чистых сканов с интервалом не менее 2,2 секунды; incomplete, empty или unknown scan сбрасывает подтверждение. Full import/resume/retry, распознавание действительно пустой истории и проверка на live Google DOM ещё не закрыты.

## 5. Удаление
Одна операция над Google и одна последующая автоматическая синхронизация; второго ручного локального удаления нет.

После отдельного апрува: найти native row по уникальному ID → открыть штатное меню → подтвердить название → вызвать Google Delete → синхронизировать. При неоднозначном ID удаление недоступно.

## 6. Защита данных и UI
- Родная история скрывается только при полном сканировании, когда все строки классифицированы и найдена стабильная строка.
- При unknown/partial history overlay скрывается, Google остаётся доступным.
- Partial load не трактуется как удаление.
- Чаты не объединяются по title или общему q.
- Legacy title-only записи сохраняются, но скрываются.
- Folder bindings сохраняются только при доказанной identity.

## 8. Браузерный прототипный harness

В v0.4.1 добавлен Playwright runner. Он запускает Chromium с установленным unpacked MV3 extension и перехватывает URL Google Search, подставляя обезличенные fixture HTML. Проверяются:
- реальный injection content script;
- stable-ID history и точное замещение native region;
- подсчёт user turns в открытой fixture-сессии;
- фильтр 2+;
- collapse/restore исходной истории;
- q-only строка, при которой расширение не закрывает native Google UI.

Этот harness доказывает поведение расширения в Chromium на контролируемом DOM, но не заменяет проверку актуальной разметки живого Google аккаунта.


## Подтверждение URL identity и lazy loading

- Chromium test fixture использует `https://google.com/search?mtid=123` как thread URL. Поэтому `mtid` — единственный принимаемый URL-параметр identity; короткое значение тоже валидно.
- Значения `q`, `udm`, `tid`, `thread`, `thread_id` и hash без mtid не используются как ключ диалога.
- Семантические DOM data-атрибуты оставлены как кандидаты, но их соответствие текущему Google DOM должно быть подтверждено live snapshot.
- Lazy-load priming накапливает ID между проходами, включая виртуализированные списки. Восемь стабильных проходов по 450 мс без новых ID/роста scrollHeight/видимой загрузки завершают обход.
- Любая DOM-мутация в native history инвалидирует полный snapshot; частичный проход не разрешает скрыть родную историю или подтверждать удаления.


## Исключение одиночных поисковых строк

Строка Google `/search?q=...` без `mtid` является URL поиска, а не URL thread. Она исключается из списка диалогов и не блокирует overlay, если найден хотя бы один подтверждённый thread ID. Если подтверждённых диалогов нет, Google сохраняет штатный список. Неоднозначные элементы по-прежнему блокируют замену native list.
