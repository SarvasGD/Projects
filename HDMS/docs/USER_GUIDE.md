# HDMS — инструкция пользователя

**Версия инструкции:** 16 ноября 2026.  
**Назначение:** как запустить локальную сборку, проверить матчап двух колод, использовать матрицу, конструктор, историю и режимы выполнения.

## 1. Что делает HDMS

HDMS — инструмент для сравнительного тестирования колод Hearthstone. Ты задаёшь одну или несколько колод, выбираешь параметры и запускаешь серии смоделированных партий. Сервис подсчитывает победы, ничьи, среднее количество ходов и другие показатели.

HDMS отвечает на вопрос: «Как эти колоды ведут себя друг против друга внутри текущей модели симулятора?» Он не подключается к игровому клиенту, не играет реальные матчи и не собирает статистику ladder. Результаты — model-based estimate, а не гарантированный прогноз реального winrate.

## 2. Запуск на Windows

Проект находится в папке HDMS/hdms-mvp.

Для обычного запуска:
1. Открой папку проекта.
2. Запусти Start HDMS.bat двойным щелчком или выполни npm run dev в терминале после npm ci.
3. Оставь окно терминала открытым: оно обслуживает локальный сайт.
4. Открой локальный адрес, который вывел Next.js, обычно http://localhost:3000.

Для обновления из GitHub используй Update HDMS.bat. Он откажется выполнять обновление, если в локальном репозитории есть незакоммиченные изменения. Не удаляй локальные изменения ради обновления, пока не выяснишь, что в них находится.

Check HDMS.bat запускает TypeScript check, тесты и production build. Это не заменяет ручное тестирование UI.

## 3. A vs B — сравнить две колоды

1. Открой главную страницу.
2. Вставь deck-код в поле «Колода A».
3. Вставь второй deck-код в поле «Колода B».
4. Выбери число партий.
5. Выбери максимальное число ходов, если хочешь изменить предел завершения партии.
6. При необходимости включи mulligan и задай порог стоимости карт, которые оставляются в стартовой руке.
7. Выбери режим выполнения — описание ниже.
8. Нажми «Запустить симуляцию».

### Что означают настройки

**Партий (games).** Чем больше партий, тем меньше случайное колебание результата при одинаковой модели и настройках. Большая серия дольше считается. Даже 1000 партий не исправят систематическую ошибку правил или стратегии.

**Max ходов.** Верхний предел одного матча в этой модели. Если партия не завершилась до лимита, она учитывается как ничья. Изменение лимита может заметно менять долю ничьих и winrate.

**Mulligan.** Упрощённый фильтр стартовой руки: карты выше выбранной стоимости возвращаются в колоду и заменяются. Это не полноценная стратегия муллигана для конкретной колоды. Настройка влияет на результат, поэтому при сравнении колод используй одинаковые параметры.

### Как читать результат

- Winrate A / B — доля всех партий, завершившихся победой соответствующей стороны.
- Draws — доля ничьих.
- «Без ничьих» — нормализованная доля побед среди только завершившихся победой партий.
- Среднее количество ходов — среднее по всем партиям, включая ничьи.
- Средний HP — средний остаток HP победителя в его выигранных партиях.
- Распределение по ходам — количество партий, закончившихся на каждом ходу.
- Пути победы A/B — текущая эвристическая классификация aggro/midrange/control/combo/mixed. Это не распознанные независимые win conditions.
- Winlines — три выбранных примера: самая быстрая победа, победа с максимальным HP и самая долгая партия с победителем. Сейчас это не все партии и не полноценные стратегические линии.

## 4. Режимы запуска — что выбрать

### Server — обычный режим

Браузер отправляет запрос серверному API локального Next.js приложения. Сервер выполняет симуляцию. Это режим по умолчанию и лучший стартовый вариант для обычного использования.

Плюс: не нужно отдельно запускать симулятор в браузерном Worker. Минус: тяжёлая синхронная симуляция выполняется на серверной стороне процесса; текущая версия не использует очередь фоновых задач с живым прогрессом.

### Web Worker — когда включать

Web Worker запускает JavaScript симуляцию в отдельном потоке браузера. Это помогает оставить интерфейс отзывчивым, пока браузер считает партии. Используй его, когда хочешь перенести вычисление A vs B из главного потока страницы.

Что важно:
- Worker использует тот же общий simulation runner и те же правила, что серверный режим.
- Он не делает игровой AI умнее и не повышает точность.
- Он не гарантирует более быстрое выполнение; скорость зависит от устройства и браузера.
- При первом запуске Worker загружает базу карт из HearthstoneJSON в свой контекст. Это может занять несколько секунд и требует сети.
- Кэш находится в памяти Worker. Перезапуск/завершение контекста может потребовать повторной загрузки.
- Нельзя считать текущую реализацию полноценным offline mode.
- Если Worker падает, интерфейс автоматически пытается выполнить серверный расчёт.

Совет: начни с Server. Включай Web Worker, если на длинном прогоне заметно подвисает интерфейс или хочешь проверить именно браузерный режим.

### Parallel — когда включать

Этот режим разбивает большой A vs B прогон на несколько независимых серверных HTTP-запросов и затем объединяет сводки. В интерфейсе доступен для 400 и более партий.

- Это не Web Worker.
- Это не Node worker_threads.
- Это не серверная очередь фоновых задач.
- Результаты батчей используют разные seed, поэтому небольшие расхождения между прогонами ожидаемы.

Не включай одновременно Worker и Parallel: интерфейс отключает параллельный режим при выборе Worker.

## 5. Матрица — сравнить несколько колод

1. Открой раздел «Матрица».
2. В каждом слоте вставь deck-код.
3. Нажми Enter или кнопку «Проверить» и дождись декодирования: должны появиться класс, формат и размер колоды.
4. При необходимости добавь ещё слоты или используй доступные пресеты.
5. Можно перетаскивать подготовленные слоты для изменения порядка.
6. Выбери число партий на каждую пару и maxTurns.
7. Нажми «Запустить».

Матрица сравнивает каждую пару колод отдельно. При N колодах выполняется N×(N−1)/2 попарных сравнений; диагональ — self-play и не считается. Процент в ячейке показывает winrate колоды строки против колоды столбца; обратная ячейка показывает результат другой стороны.

Текущие ограничения:
- Матрица выполняется серверным API, Web Worker для неё не подключён.
- История матриц пока не сохраняется в доступный пользователю список истории.
- Для каждой пары используется заданное число партий; большая матрица быстро увеличивает общий объём расчёта.

## 6. Конструктор колод

Открой «Конструктор», импортируй существующий deck-код или начни редактирование, найди карты через поиск и добавляй/удаляй их. Конструктор предназначен для изменения списка карт и быстрого повторного тестирования.

После изменений проверь размер и формат колоды. Возможности оценки замен зависят от текущей реализации; не считай рекомендации автоматическим оптимизатором, пока такой механизм явно не показан в интерфейсе.

## 7. История, сохранение и экспорт

После A vs B результата нажми «Сохранить тест». Запись появится в разделе «История».

Важно:
- История сохраняется в IndexedDB текущего браузера.
- История не переносится автоматически на другой компьютер/браузер.
- В текущей модели история хранит summary и deck-коды, а не полные журналы всех сыгранных партий.
- Матрицы в этот список пока не входят.
- JSON export предназначен для сохранения структурированного результата.
- PNG export сохраняет изображение текущей панели результата.

## 8. Известные ограничения результата

1. HDMS — упрощённая модель игры, а не официальный симулятор Blizzard.
2. Выбор карт и торгов основан на ограниченных эвристиках, а не на реальном игроке/полном AI.
3. Не все карточные эффекты распознаны или протестированы.
4. Discover и секреты упрощены; детали см. 07_rules_and_approximations.md.
5. WinPath пока не распознаёт отдельные линии победы внутри одной колоды.
6. Журнал партии обрезан до последних 15 записей и не позволяет воспроизвести полный бой.
7. Количество партий уменьшает случайный шум, но не устраняет систематическое смещение модели.

## 9. Если что-то не работает

- **Код колоды не декодируется:** проверь, что скопирован полный deck-код без пробелов/лишнего текста; удостоверься, что карта и формат поддерживаются текущей базой.
- **Матрица не стартует:** проверь, что оба кода декодированы и рядом с каждым слотом показан класс и количество карт; если состояние слота застряло, перезагрузи страницу и повтори. После обновления проекта проверь версию фикса.
- **Worker долго загружает карты:** проверь доступ к HearthstoneJSON и попробуй обычный Server режим.
- **Расчёт упал:** смотри сообщение в UI и терминал, где запущен Next.js. Скопируй сообщение ошибки и шаги воспроизведения.
- **История пуста:** убедись, что после A vs B ты нажал «Сохранить тест» и открыл тот же браузерный профиль.
