# 05 — Task Pack для агента Квена

**Статус:** первоначальный план разработки, октябрь 2026.  
**Важно:** не начинать повторно с Task 0. Проект уже содержит работающий MVP-код. Сопоставление первоначальных задач с текущим состоянием и активные приоритеты находятся в 09_roadmap.md.

## Как использовать этот документ сейчас

- Task 0–4 — базовый bootstrap, загрузка карточных данных, парсинг deck-кодов, CRUD и анализ колоды. Эти пункты нельзя считать завершёнными только по старому плану; фактическое состояние смотреть в README MVP и 04_tech_spec.
- Task 5–6 — ядро matchup и хранение тестов. Симуляция есть, но полнота модели и хранение всех партий не подтверждены.
- Task 7 — winline extraction. В текущем коде есть только три выбранные записи с обрезанными логами; задача выполнена частично.
- Task 8 — матрица. API/расчёт есть; UI-ввод требовал исправления; после исправления нужен browser test.
- Task 9–10 — конструктор и цикл правки/тестирования. Есть частичная реализация, не считать автоматическим оптимизатором колод.
- Task 11–12 — пять/шесть policy по архетипам и hybrid. В текущем коде отдельного policy.ts не найдено; эти задачи не считать выполненными.
- Task 13 — Docker и документация. Dockerfile, Compose, CI и локальные BAT-файлы добавлены; документация обновляется по фактическому коду.

## Правило выполнения

Не начинать большую следующую функцию, пока не описан acceptance criterion и способ проверки. Исправления могут объединяться в один коммит, если они относятся к одной связанной проблеме. Для каждой задачи фиксировать: исходная проблема, изменённые файлы, тесты, результат CI, оставшиеся ограничения.

## Task 0 — Bootstrap

- Init Next.js 14 (App Router, TS, ESLint, Tailwind), Prisma + SQLite, Vitest, shadcn/ui.
- README с командами запуска и проверки.

**Исторический acceptance:** dev server запускается; миграция БД создаётся; тесты проходят.  
**Текущая оговорка:** в активном MVP Prisma/SQLite нет; это требование старой архитектуры, не текущая реализация.

## Task 1 — Card data service

- Загрузка ruRU/enUS card JSON и локальный cache.
- Поиск и выбор карт, получение карт для деки.

**Текущая оговорка:** код активного MVP загружает ruRU collectible JSON по сети и кэширует в памяти; постоянный локальный snapshot и полноценный update script не подтверждены.

## Task 2 — Deck code parser

- Decode/encode и round-trip tests.

**Текущий статус:** декодирование и кодирование присутствуют; формат Standard/Wild должен проверяться тестами и на реальных кодах.

## Task 3–4 — Deck CRUD and analysis

- Сохранение колод и анализ кривой/типов/редкости.

**Текущая оговорка:** реализованы раздел Builder и базовое отображение/поиск, но серверного Deck CRUD из старой схемы Prisma нет.

## Task 5–6 — Matchup core and persistence

- A vs B Monte Carlo.
- Хранение истории и summary.

**Текущий статус:** симуляция есть; сохранение summary выполняется в IndexedDB. Точные игровые правила, полнота log и все партии не хранятся.

## Task 7 — Winlines

- Извлечь репрезентативные партии и отображать их журналы.

**Текущий статус:** частично. Есть fastest / longest / highest HP, но журналы обрезаны до последних 15 записей. Нет полного реплея и нескольких идентифицированных линий победы.

## Task 8 — Matrix

- Winrate matrix по загруженным колодам.

**Текущий статус:** вычислительная функция и API есть, проверены unit tests на fixtures. UI исправлен в текущей ревизии; требуются browser E2E и локальная проверка после обновления.

## Task 9–10 — Builder and quick iteration

- Конструктор, правка колоды, повторный тест и delta.

**Текущий статус:** базовые функции присутствуют; качество и полноту workflow проверить отдельно.

## Task 11–12 — Archetype policies

- Агро, темпо, мидрейндж, контроль, комбо, гибрид.

**Текущий статус:** не реализованы как отдельная система policy. Сейчас используется упрощённая эвристика выбора действий внутри engine.ts.

## Task 13 — Deploy & docs

- Docker, Compose, docs.

**Текущий статус:** Dockerfile/Compose и CI присутствуют; Windows BAT scripts добавлены, но их выполнение на компьютере владельца — отдельная локальная проверка.
