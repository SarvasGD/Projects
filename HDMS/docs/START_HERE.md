# HDMS — точка входа в проект

**Актуальность:** 17 ноября 2026.

Этот файл заменяет старую инструкцию «начать с Task 0». Bootstrap и базовые части приложения уже созданы; текущая задача — довести действующий MVP до проверяемого симулятора с понятной диагностикой.

## Порядок чтения

1. PROJECT_GOVERNANCE.md — обязательные правила работы с репозиторием и передачи контекста.

2. 01_vision.md — продуктовая задача и границы.
3. 03_competitor_analysis.md — сравнительный анализ и UX-референсы.
4. 04_tech_spec.md — фактическая архитектура текущего кода.
5. 07_rules_and_approximations.md — что именно моделируется и что не подтверждено.
6. 09_roadmap.md — текущее состояние, приоритеты и критерии статусов.
7. ../reverse-engineering/README.md — пакет ТЗ для деконструкции, матрица доноров и clean-room-процесс.
8. REVERSE_ENGINEERING_PLAN.md — вспомогательные инструменты исследования UI и winlines.
9. USER_GUIDE.md — как проверять локальный продукт и режимы запуска.
10. 05_task_pack.md — исторический первоначальный пакет задач; использовать как источник требований, а не как текущую последовательность с Task 0.

## Активный приоритет

Начинать с P0 из 09_roadmap.md:
- браузерные smoke tests и проверка матрицы;
- полный журнал событий партии;
- несколько независимых winlines и смешанные линии;
- проверка Server/Worker parity;
- реестр покрытия эффектов и предупреждения.

## Правила работы

- Не выдумывать наличие функции по названию файла или старому документу.
- Отделять «реализовано» от «проверено» и «точно моделируется».
- Не считать прохождение TypeScript/build доказательством точности игровых правил.
- Любая механика получает статус Done только при наличии проверяемого теста.
- Русские названия карт — приоритет, если они доступны в базе ruRU.
- Все результаты симуляции маркируются как model-based estimate.
