# 01 — Видение продукта

## Что такое HDMS

**HDMS (Hearthstone Deck Matchup Simulator)** — это калькулятор сравнения колод Hearthstone в формате Стандарт. Пользователь загружает две колоды по deck-коду, запускает Monte Carlo-симуляцию, и получает:

- Winrate колоды A против колоды B;
- Распределение ходов победы (гистограмма);
- Средний HP на победе;
- Winlines — 3–5 репрезентативных партий с полным логом по ходам.

## Ключевая идея

Игрок может **скрытно и безопасно** проверять гипотезы колод до выкатки в игру. Это **проверка гипотез**, а не сбор статистики реальных игр (как у HSReplay) и не запись своих матчей (как у HDT).

## Позиционирование

| Аспект | Значение |
|---|---|
| Формат | Стандарт (Вольный — позже, Итерация 3) |
| Аудитория | Игроки, которые хотят тестировать колоды до игры |
| Конкуренты | HSReplay, HDT, Firestone, FindStone, hearthstone-oracle |
| Отличие от конкурентов | **Единственный** сервис с симуляцией matchup A vs B |
| Юридический статус | Не нарушает ToS Blizzard (не бот, не автоматизация игры) |

## Цели

### Продуктовые
- MVP с рабочим matchup-симулятором — за 2–2.5 недели.
- Полноценный продукт с конструктором и быстрым циклом тестов — за 4–5 недель.
- Все архетипы (aggro/tempo/midrange/control/combo) — за 7 недель.

### Коммерческие
- **$1000 в первый месяц после выкатки.**
- Модель: разовый Lifetime Deal для первых пользователей + подписка для новых.
- Площадка: PWA + собственный сайт через Paddle (Merchant of Record).

## Принципиальные ограничения

- Симуляция **model-based**, не полноценный движок правил Blizzard.
- Точные механики: мана, добор, усталость, бой, Провокация, Божественный щит, Рывок, Натиск, Неистовство ветра, Боевые кличи, Предсмертные хрипы, Комбо (как триггер), Перегрузка, зарядка силы героя (1–10 уровней), Rewind, бафы/дебафы, броня, лечение.
- Упрощённые механики: секреты, Discover, копирование карт.
- Полный стек приоритетов Blizzard — **не реализуем**.

## Итоговый вывод

1. По базовым функциям HDMS не уступает конкурентам.
2. По визуальному конструктору — конкурирует с FindStone и Firestone.
3. **По симуляции matchup (winrate, ход, HP) — единственный.** Это уникальное торговое предложение.
4. По winlines — единственный, кто генерирует их из симуляции, а не из реальных игр.
5. **По быстрому циклу «правка → тест → дельта winrate» — единственный.** Killer-фича.

7. По мобильности (PWA) — выигрывает у HDT/Firestone (десктоп), проигрывает FindStone (нативный iOS).
8. По цене — может конкурировать с бесплатными через Free+Premium ($3–5/мес).

  hpLoser    Int
  log        Json
  testRun    TestRun @relation(fields: [testRunId], references: [id])
}

## Симуляция: спецификация

### Goldfish (Прототип, фича #2 частично)

- Вход: колода + параметры (ход первый / на монете, mulligan).
- Выход: `{ drawProbabilities, comboAssemblyTurn, damagePerTurn[] }`.
- Monte Carlo N = 10 000, seed фиксируемый.
- Модель: «голодная» игра карт по кривой, без противника.

### Matchup (Прототип, фича #2)

**Состояние игрока:**
```
{ hp, armor, mana, maxMana, heroPowerLevel,
  hand: Card[], deck: Card[], board: Minion[],
  fatigue, weapon?, mulliganDone: bool }
```

**Разрешение карт (effectRegistry):**
Каждая карта имеет обработчик `(state, owner, target?) => state` в `effects.ts` по `dbfId`. Для неизвестных — фолбэк по тегам текста (damage / draw / heal / summon / buff / manaGain).

**Ручные обработчики (обязательно в Task 6):**
- Рыцарь Горького Цветка
- Бесчисленные возможности
- Зазубренное лезвие времени
- Морхи
- МАТРИАРХ
- Разрушитель Перекрёстка
- Прозорливый дракозмей
- Темночешуйчатая праматерь

**Turn loop:**
1. Start: `maxMana = min(10, maxMana+1)`, `mana = maxMana`, draw 1, fatigue если пусто.
2. Play loop: пока есть играбельные карты → score → play best → check lethal.
3. Attack loop: minions → trade или face по policy.
4. Hero power если mana ≥ cost.
5. End: сброс временных бафов, `turn++`.

**AI policy (`policy.ts`):**
- `aggro`: face > trade, приоритет урону.
- `tempo`: оптимальный trade по ratio, pressure.
- `midrange`: mix, зависит от HP противника.
- `control`: ремувал, heal, торг по HP.
- `combo`: протект combo-кусков, добор под ключ, lethal-check.
- `hybrid`: адаптивный (Task 12).

**Win conditions:**
- HP ≤ 0
- Fatigue death
- `maxTurns` (по умолчанию 30) → draw (или сравнение HP).

**Monte Carlo:**
- N партий (1000 по умолчанию, до 20 000), seed фиксируемый.
- Агрегация: `winrate`, распределение ходов, распределение HP, средний ход победы.

**Winlines:**
Из N партий выбираются:
- самый быстрый выигрыш A
- самый быстрый выигрыш B
- победа A с максимальным HP
- победа B с максимальным HP
- «медианная» партия

Log = `[{ turn, player, action, detail, hpA, hpB, boardSummary }]`.

# 07 — Правила и аппроксимации симуляции

## Точные механики (реализуются полностью)

- Ресурсы: мана-кристаллы, оверлоад, монеты, базовые «раскопки».
- Добор, перебор, усталость (fatigue).
- Боевая система: атака существ, размены, Провокация, Неуязвимость, Рывок, Натиск, Неистовство ветра.
- Боевые кличи, Предсмертные хрипы, Комбо (как триггер), Перегрузка.
- Урон, лечение, броня, бафы/дебафы атаки и здоровья.
- Зарядка силы героя (Imbue) — уровни 1–10, усиление эффекта.
- Rewind (механика 2026): заклинание срабатывает дважды с рандомным исходом; Морхи сохраняет оба исхода.
- Триггеры: «после того как», «в начале хода», «в конце хода».
- Deathrattles, базовые Discover-эффекты (3 карты из пула).
- Базовые трансформации (Hex, Polymorph) — без цепочек «трансформировали существо с deathrattle → сработал deathrattle».
- Silence — снимает все эффекты, но не снимает aura.

## Упрощённые механики (моделируются приближённо)

- **Секреты:** срабатывают по первому подходящему условию, без полного стека приоритетов.
- **Discover:** случайный выбор из отфильтрованного пула, без «умного» выбора.
- **Копирование карт** (в руку, в колоду, в руку противника) — без рекурсивных цепочек.
- **Замещение (Overload → Mana Saber и т.п.)** — только базовые взаимодействия.

## Что НЕ реализуется

- Полный стек приоритетов Blizzard (тайминг триггеров, «кто первый в очереди»).
- Рекурсивные бесконечные цепочки (копирование карты, которая копирует карту).
- Точный AI Blizzard-бота (используется свой AI по архетипу).

# 08 — Правила работы с MCP и агентскими чатами

## Жёсткое правило

**MCP и агентский режим нельзя совмещать в одном чате.**

## Решение — два параллельных чата

| Чат | Что делается |
|---|---|
| **Обычный чат с MCP** | Сбор UI-паттернов через `design-system-extractor`, работа с внешними источниками, ресёрч |
| **Агентский чат** | Написание кода, рефакторинг, выполнение задач из `05_task_pack.md` |

## Процедура

1. **MCP-задачи** (сбор UI-паттернов, ресёрч) — в обычном чате с MCP.
2. Результат MCP-задачи (скриншоты, дизайн-токены, markdown-файл) передаётся в агентский чат как входные данные.
3. **Агентские задачи** (Task 0–13) — в агентском чате.

## Пример workflow

```
[Обычный чат с MCP]
Задача: собрать UI-паттерны с Firestone, FindStone, HSReplay через design-system-extractor.
Результат: design.md + аннотированные скриншоты.
    ↓
[Агентский чат]
Task 9 (Deck builder): использовать design.md как референс для вёрстки.
```

## Учтённые риски

- **Не проверено на практике.** Разделение может потребовать уточнения после первых прогонов.
- **При проблемах** — фиксировать в этом файле, обновлять процедуру.

## Что нельзя

- Пытаться совместить MCP и агентский режим в одном чате.
- Переключаться «на лету» — только через отдельный чат.

### Шаг 2: Начни с Task 0

Task 0 — Bootstrap проекта. Следуй acceptance-критериям буквально.

### Шаг 3: Отчитайся после Task 0

Формат отчёта:
- Дерево файлов.
- Результат каждого acceptance-критерия (пройден/не пройден).
- Открытые вопросы.

### Жёсткие правила

1. **Задачи — последовательно.** Не начинать следующую, пока предыдущая не пройдёт acceptance.
2. **Не выдумывать.** Если не уверен — спросить.
3. **MCP и агентский режим — в разных чатах.** Не совмещать.
4. **Плашка «model-based estimate»** — обязательна на всех экранах результатов.
5. **Русские названия карт** — приоритетные.

### Что НЕ делать

- Не реализовывать полный стек приоритетов Blizzard.
- Не добавлять Поля Сражений, Арену, Дуэли.
- Не использовать неактуальные карты (добавлять по актуальному Стандарту).
