# HDMS — пакет деконструкции публичных проектов

**Редакция:** 16 ноября 2026  
**Назначение:** комплект для передачи отдельному агенту-реверс-инженеру, затем независимому агенту-проверяющему и после утверждения — агенту-разработчику.

## С чего начинать

1. [ТЗ на деконструкцию](./01_TZ_REVERSE_ENGINEERING.md) — основной документ задания. Его получает реверс-инженер.
2. [Матрица доноров и функций](./02_DONOR_ASSIGNMENTS.md) — закрытый перечень источников, строгое распределение функций и зафиксированные сведения о лицензиях.
3. [Шаблон нейтральной спецификации](./03_FUNCTION_SPEC_TEMPLATE.md) — формат результата по каждой функции.
4. [Журнал источников и доказательств](./04_EVIDENCE_REGISTER_TEMPLATE.md) — служебный реестр происхождения и подтверждений. Не передаётся разработчику.
5. [Протокол третьего агента-проверяющего](./05_INDEPENDENT_REVIEW_PROTOCOL.md) — отдельный этап перекрёстной проверки готовых спецификаций.
6. [Clean-room и передача в разработку](./06_CLEAN_ROOM_HANDOFF.md) — обязательные границы между контурами.

## Зафиксированная схема процесса

`Реверс-инженер` → `Третий агент-проверяющий` → `Утверждённые спецификации` → `Агент-разработчик`

- Реверс-инженер исследует назначенный ему основной донор и не проводит сравнительный анализ остальных доноров.
- Третий агент независимо проверяет результаты, в том числе может сопоставлять их с другими разрешёнными источниками из закрытого перечня.
- Разработчик не получает исходники, ссылки на исходные файлы, рабочие заметки и служебный журнал доноров. Он получает только утверждённые спецификации и тестовые сценарии.
- FindStone и HSReplay исключены из исследования всеми участниками.

## Граница между семью функциями и полной физикой карт

Семь функций взяты из таблицы «Что скопировать» в `HDMS/docs/03_competitor_analysis.md`. Они сохраняются как семь отдельных исследовательских пакетов.

Полная модель игровых правил и карточных взаимодействий — отдельная сквозная задача ядра HDMS. Она не сводится к наличию реестра эффектов: реестр показывает, что поддержано и проверено, а движок обязан правильно разрешать сами эффекты и их взаимодействия. Для этой отдельной задачи назначен MetaStone как единственный основной донор реверс-инженера.

## Статус

Пакет подготовлен как задание к исследованию. Ни одна из будущих спецификаций не считается готовой только по факту наличия этого комплекта. Статусы «подтверждено», «частично» и «неизвестно» проставляются по результатам исследования и независимой проверки.
