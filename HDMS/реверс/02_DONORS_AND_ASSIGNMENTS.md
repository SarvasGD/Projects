# Доноры и назначения для деконструкции HDMS

**Дата фиксации проектного распределения:** 17 ноября 2026.  
**Правило:** одна функция — один основной донор. Распределение не менять самостоятельно.

## 1. Закрытый перечень публичных доноров

| Донор | Канонический публичный репозиторий | Лицензия / текущая квалификация |
|---|---|---|
| Hearthstone Deck Tracker (HDT) | https://github.com/HearthSim/Hearthstone-Deck-Tracker | Не считать open source: в README указано All Rights Reserved |
| Firestone | https://github.com/Zero-to-Heroes/firestone | Лицензия не подтверждена; в проектном аудите не найдено однозначного LICENSE/COPYING, считать не-OSS до подтверждения владельцем |
| hearthstone-oracle | https://github.com/gregario/hearthstone-oracle | MIT |
| Fireplace | https://github.com/jleclanche/fireplace | GNU AGPL-3.0 |
| MetaStone | https://github.com/demilich1/metastone | GNU GPL-2.0 |

Это перечень разрешённых источников для функционального исследования, а не разрешение повторно использовать код, тексты, графику или данные. Публичный доступ, доступность исходного кода и open-source-статус — разные понятия. Проверяй актуальные LICENSE/COPYING и лицензии отдельных материалов на момент конкретного исследования. Не считай лицензию репозитория автоматически применимой к карточным данным, изображениям и сторонним зависимостям.

## 2. Семь целевых функций

| № | Функция | Единственный основной донор | Исследовательский срез |
|---|---|---|---|
| 1 | Плагинная архитектура | HDT | Расширения, жизненный цикл, точки интеграции, события, конфигурация, совместимость, изоляция сбоев |
| 2 | Визуальный конструктор колод | Firestone | Создание/редактирование колоды, добавление/удаление/замена, поиск, фильтры, слоты, валидация, состояния |
| 3 | Визуализация мана-кривой | Firestone | Группировка стоимости, подсчёт, пересчёт, синхронизация с колодой, интерактивность, edge cases |
| 4 | Сбор пользовательской матчевой статистики | HDT | Фиксация матчевых событий, структура локальной записи, настройки, импорт/экспорт и история |
| 5 | Реестр эффектов карт | Fireplace | Каталог карт/механик, триггеры, условия, цели, повторное использование, тестирование и покрытие |
| 6 | LLM-ассистент анализа архетипа | hearthstone-oracle | Декодирование, карточные факты, стратегические знания, определение архетипа, объяснение выводов |
| 7 | UI-паттерны Hearthstone companion | Firestone | Навигация, информационная иерархия, состояния карточек, подсказки, ошибки, responsive и accessibility |

Firestone назначен тремя отдельными функциями, но каждый пакет исследуется как самостоятельная задача. Не смешивай конструктор, кривую и companion UI в одну спецификацию.

## 3. Отдельная сквозная задача симуляционного ядра

| Задача | Единственный основной донор | Назначение |
|---|---|---|
| Полная физика игры, правила матча и взаимодействия карточных эффектов | MetaStone | Жизненный цикл партии, игровые зоны, сущности, действия, бой, события, триггеры, разрешение эффектов, смерть, случайность, карточная полнота |

Это самостоятельная центральная задача HDMS, не заменяемая функцией № 5 «Реестр эффектов карт». Для физики игры реверс-инженер работает только по MetaStone. Fireplace и остальные доноры могут проверяться только контролёром в отдельном независимом контуре.

## 4. Исключённые источники

**FindStone и HSReplay исключены для всех участников**. Не искать их закрытые механизмы, backend, API, обходы доступа и не использовать их для заполнения пробелов. Не приписывать HDT функциональность HSReplay.

## 5. Правило пробела

Если назначенный донор не содержит нужного поведения, код недоступен, сведения устарели или доказательство недостаточно:
1. зафиксируй Not found / Unknown / Partial;
2. укажи, какие файлы и сценарии были проверены;
3. не открывай другой донор и не закрывай пробел собственным предположением;
4. вынеси вопрос независимому контролёру;
5. оставь продуктовое решение владельцу HDMS.

## 6. Фиксация версии источника

В начале каждого задания зафиксируй:
- canonical URL;
- ветку или tag;
- commit SHA;
- дату фиксации;
- лицензионный файл и его статус;
- фактически просмотренные каталоги, файлы и тесты.

Все доказательства должны быть привязаны к этому snapshot. Не используй ссылку на изменяемую ветку main как единственное подтверждение.
