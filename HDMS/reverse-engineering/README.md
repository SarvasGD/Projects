# HDMS — пакет деконструкции публичных проектов

**Редакция:** 17 ноября 2026  
**Назначение:** комплект для передачи реверс-инженеру, независимому проверяющему и затем агенту-разработчику. Общий порядок ведения проекта задаёт [PROJECT_GOVERNANCE.md](../docs/PROJECT_GOVERNANCE.md).

## С чего начинать

1. [ТЗ на деконструкцию](./01_TZ_REVERSE_ENGINEERING.md) — основное задание реверс-инженеру.
2. [Матрица доноров и функций](./02_DONOR_ASSIGNMENTS.md) — пять проектов, семь функций, отдельная задача полной физики, распределение ролей и лицензии.
3. [Шаблон нейтральной спецификации](./03_FUNCTION_SPEC_TEMPLATE.md) — формат результата по каждой функции.
4. [Журнал источников и доказательств](./04_EVIDENCE_REGISTER_TEMPLATE.md) — служебный реестр происхождения и подтверждений. Не передаётся разработчику.
5. [Протокол третьего агента-проверяющего](./05_INDEPENDENT_REVIEW_PROTOCOL.md) — отдельный этап перекрёстной проверки готовых спецификаций.

## Зафиксированная схема процесса

`Реверс-инженер` → `Третий агент-проверяющий` → `Утверждённые спецификации` → `Агент-разработчик`

- Реверс-инженер исследует только назначенного основного донора по каждой функции. Сравнительный анализ других доноров ему запрещён.
- Проверяющий получает доступ на чтение ко всем пяти разрешённым донорам, спецификациям и evidence register. Он независимо проверяет результат и при необходимости выполняет точечную перекрёстную сверку. Реверс-инженер ограничен назначенным донором.
- Владелец HDMS утверждает продуктовые решения и закрывает неоднозначности.
- Разработчик не получает исходники, ссылки на исходные файлы, рабочие заметки и служебный журнал доноров. Он получает только утверждённые нейтральные спецификации, тесты и разрешённые данные.
- FindStone и HSReplay исключены из исследования всеми участниками.

## Пять проектов и open-source статус

Все пять входят в фиксированный периметр публичных проектов для исследования. Это не означает, что все пять являются open source: подтверждённые open-source лицензии есть у hearthstone-oracle (MIT), Fireplace (AGPL-3.0) и MetaStone (GPL-2.0). У HDT в README указано All Rights Reserved; для Firestone в корневой структуре лицензия не обнаружена. См. точные сведения и ограничения в [матрице доноров](./02_DONOR_ASSIGNMENTS.md).

## Семь функций и полная физика

Семь функций сохраняются как семь самостоятельных исследовательских пакетов. Полная модель игровых правил и карточных взаимодействий — отдельная сквозная задача ядра HDMS, не подменяемая реестром эффектов. Для неё основной донор реверс-инженера — MetaStone; независимую перекрёстную проверку выполняет третий агент.

Roadmap HDMS: [P0.4 — Полнота моделирования игровых правил и карточных взаимодействий](../docs/09_roadmap.md). Это центральная цель развития симуляционного ядра: поддержка всех карт и их взаимодействий в пределах поддерживаемых Constructed-форматов. Реестр покрытия, тесты и предупреждения — инструменты достижения и контроля этой цели.

## Статус

Пакет подготовлен как задание к исследованию. Ни одна будущая спецификация не считается готовой только по факту наличия этого комплекта. Статусы «подтверждено», «частично», «неизвестно» и «требует проверки» устанавливаются по результатам исследования и независимой проверки.
