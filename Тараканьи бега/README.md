## Текущее положение

Основной игровой цикл, пять режимов, тараканы, мутации, угрозы, хищники, босс, Гнездо, локальные сохранения и RU/EN уже реализованы. QA основного прототипа выполнен Agent-Qwen; повторно проводить полный QA как отдельный этап сейчас не требуется. После последующих существенных изменений выполняется только регрессионная проверка затронутых систем.

Ближайшие продуктовые задачи:

1. Исправить управление мышью.
2. Сделать понятными зоны и их эффекты на игровом столе.
3. Усилить читаемость, появление и давление босса «Бабушка».
4. Подготовить встроенную версию игры для портфолио с автоматическим обновлением при изменениях проекта.
5. Подготовить проект к Web MVP, затем к софт-лончу и привлечению инвестиций.

## Правила разработки

- `roach-rush.html` — текущая каноническая игровая сборка и основной объект разработки.
- Не восстанавливать структуру из 16 частей, `build.sh` или старого README: это неактуальное описание. Текущий проект не обязан становиться модульным ради соответствия старой документации.
- Ничего из старых файлов и архивов пока не удалять. Их назначение и статус отражены в реестре.
- Матрица разработки объединяет фичер-лист, этапы, статусы и исполнителей. Отдельный дублирующий roadmap или второй статусный документ не вести.
- Реклама и рекламная монетизация относятся к софт-лончу. В текущий прототип и Web MVP их не добавлять.
- Пользователь проверяет результаты на крупных контрольных точках, а не отдельные изменения.
- Все важные продуктовые решения, правила и результаты работы чатов сразу фиксировать в документах проекта.

## Портфолио и защита исходников

Планируемая схема: приватное хранилище исходного кода → автоматическая подготовка публичной игровой сборки → публикация на отдельном игровом адресе → встраивание адреса через iframe в портфолио. После первоначальной настройки обновление должно происходить автоматически при изменении основной версии.

Важно: полностью запретить копирование кода клиентской браузерной игры технически нельзя — браузер получает исполняемый код. Приватный репозиторий, отдельный хостинг, сборка, минификация и обфускация убирают прямую ссылку на исходники и затрудняют обычное копирование, но не дают абсолютной защиты. Сейчас текущий HTML находится в публичном репозитории Projects, то есть уже доступен для скачивания. Перенос исходников в приватное хранилище и публикацию отдельного артефакта нужно выполнить до включения портфолио.

## Чего сейчас не делаем

- Не внедряем рекламную сеть и рекламные SDK до софт-лонча.
- Не добавляем аналитику в текущий прототип только ради технической полноты; она нужна к софт-лончу.
- Не начинаем мобильную и Steam-разработку до проверки Web MVP и продуктовых показателей.
- Не создаём онлайн-мультиплеер, лидерборды и сезонные системы до подтверждения необходимости.
- Не делаем мелкие задачи отдельными делегированиями и не создаём множество GitHub Issues для каждого исправления.
