# Портфолио и автоматическая публикация Roach Rush

Обновлено: 25.11.2026.  
Назначение: зафиксировать архитектуру, при которой игра автоматически обновляется в портфолио после изменения основной версии, а исходный проект не лежит в открытом доступе как единственный источник.

## Цель

В портфолио должна быть встроена работающая игра, а не скачиваемый исходный HTML. После первоначальной настройки владелец проекта продолжает обычную разработку и синхронизирует изменения в GitHub Desktop. Публикация игровой версии и её обновление выполняются автоматически.

Пользователь не должен при каждом обновлении копировать HTML в папку портфолио или вручную менять ссылку в CV.

## Рекомендуемая схема

```
Приватный GitHub-репозиторий с исходным кодом игры
                    |
                    | push в main
                    v
          Cloudflare Pages Git Integration
                    |
                    | build / minify
                    v
       Публичный игровой артефакт (dist/index.html)
                    |
                    | постоянный URL
                    v
         iframe на странице портфолио / CV
```

### 1. Приватное хранилище исходников

Создать отдельный приватный GitHub-репозиторий для источника игры. Рекомендуемое имя можно выбрать при создании, например `Roach-Rush-Source`.

В нём хранится канонический исходник и всё необходимое для сборки. Публичный репозиторий `SarvasGD/Projects` больше не должен быть единственным местом, куда публикуется актуальный редактируемый код.

**Важное ограничение текущего состояния:** файл `Тараканьи бега/roach-rush.html` уже размещён в публичном репозитории Projects, а его предыдущие версии находятся в публичной Git-истории. Перенос будущей разработки в приватный репозиторий защитит новые версии и исходники от прямого просмотра, но не сделает уже опубликованный код секретным задним числом. Удаление файла из текущей версии публичного репозитория также не удаляет его автоматически из истории. Переписывать историю Projects и удалять публичные объекты без отдельного решения владельца не следует.

### 2. Автоматическая сборка публичной версии

При каждом push в производственную ветку приватного репозитория запускается сборка:

1. Проверить HTML и встроенный JavaScript.
2. Подготовить `dist/index.html` из канонического игрового HTML.
3. Минифицировать HTML, CSS и встроенный JS. Сохранять идентификатор сборки.
4. Публиковать только `dist/`, не исходники, документацию, тестовые данные или проектные заметки.

Для первой версии достаточно минификации. Обфускацию не включать автоматически: она повышает риск поломки игры и усложняет отладку. Её можно отдельно проверить позднее, если это действительно даст пользу.

### 3. Хостинг игры: Cloudflare Pages

Рекомендуемый вариант — Cloudflare Pages с подключением приватного GitHub-репозитория через Git Integration.

Ожидаемая конфигурация:

- Production branch: `main`.
- Build command: `npm ci && npm run build:game`.
- Build output directory: `dist`.
- Production URL: постоянный адрес проекта Pages или подключённый домен.
- Preview deployments: включены для тестовых веток, если они будут использоваться.

Git-интеграция Pages автоматически запускает сборку и публикацию после push в подключённую ветку. Cloudflare Pages поддерживает как приватные, так и публичные GitHub-репозитории. Важно выбрать именно Git Integration при создании проекта: переключиться с неё на Direct Upload позже нельзя. Для подключения нужно один раз установить Cloudflare Workers & Pages GitHub App на нужный GitHub-аккаунт с доступом только к выбранному приватному репозиторию и отдельно авторизовать приложение в пользовательском аккаунте GitHub.

Документация:
- https://developers.cloudflare.com/pages/configuration/git-integration/
- https://developers.cloudflare.com/pages/configuration/git-integration/github-integration/
- https://developers.cloudflare.com/pages/get-started/git-integration/

### 4. Интеграция в существующий CV — фактическая структура проверена

**Репозиторий:** [SarvasGD/CV](https://github.com/SarvasGD/CV)  
**Публичный сайт:** https://sarvasgd.github.io/CV/  
**Текущая версия HTML при аудите:** `Site_Build_Final_v23`, файл `index.html`.  
**Данные сайта:** `content.md`.

CV уже устроен как data-driven сайт:
- `content.md` хранит RU/EN-контент, таблицу проектов, таблицу результатов, изображения и порядок карточек;
- `index.html` разбирает Markdown и строит карточки витрины функцией `cardHTML(p)`;
- порядок витрины задаётся разделами `Порядок витрины` и `Project Showcase Order EN`.

Поэтому игровой HTML не нужно копировать в CV и не нужно встраивать в каждую карточку. Целевая интеграция:

1. Добавить Roach Rush в RU- и EN-таблицы проектов как проект №16, статус «Прототип / Prototype», платформа Web. Не указывать выручку, retention или другие показатели, которых пока нет.
2. Добавить краткое описание результата в RU- и EN-разделы проектов-результатов. Все количественные данные должны описывать только проверенные функции, а не коммерческий успех.
3. Добавить №16 в начало обоих списков порядка витрины. Изображение можно добавить позднее: без него текущий CV уже умеет показывать текстовую обложку проекта.
4. В `cardHTML(p)` распознавать только карточку Roach Rush. Если поле «Ссылка на проект / Project Link» пустое или содержит тире, показывать нейтральное «ДЕМО ГОТОВИТСЯ / PLAYABLE DEMO IN PREPARATION».
5. Когда в этом поле появится постоянный HTTPS-адрес игровой сборки, вместо обычной внешней ссылки показывать кнопку «ИГРАТЬ / PLAY».
6. Кнопка открывает общее окно `<dialog>` с одним iframe. Адрес берётся из поля проекта, допускается только HTTPS. При закрытии окна iframe выгружается, чтобы игра не продолжала работать в фоне.
7. После однократного внесения стабильного URL в `content.md` дальнейшие релизы игры не требуют изменений CV: тот же URL начинает отдавать новую версию после автоматической публикации хостингом.

Таким образом, CV остаётся витриной и оболочкой, а сама игра размещается отдельно. Публичный игровой HTML не становится частью репозитория CV.

#### Предлагаемая запись в витрине CV

До публикации игровой сборки поле Project Link остаётся пустым (тире), чтобы CV не ссылался на публичный исходник игры.

| Поле | RU | EN |
|---|---|---|
| № | 16 | 16 |
| Проект | Тараканьи бега / Roach Rush | Roach Rush |
| Жанр | Аркада-рогалик | Arcade roguelite |
| Платформа | Веб | Web |
| Монетизация | – | – |
| Статус | Прототип | Prototype |
| Компания | Личный проект | Personal project |
| Период | 2026 – н.в. | 2026 – present |
| Должность | Гейм-дизайнер, AI-разработчик | Game Designer, AI-assisted Developer |

Предлагаемый текст результата без выдуманных коммерческих метрик:

- RU: «Самостоятельно создан игровой прототип: 5 режимов, 6 тараканов, 32 мутации, 11 типов угроз, 3 хищника, босс и мета-прогрессия. Разработка и проверка организованы с помощью AI-агентов. Данные по аудитории и коммерческим результатам пока не собирались».
- EN: «Independently built playable game prototype: 5 modes, 6 roaches, 32 mutations, 11 hazard types, 3 predators, a boss and meta-progression. Development and QA are coordinated with AI agents. Audience and commercial results have not yet been measured».

ID 16 ставится первым в обоих списках порядка витрины. Иллюстрация на первом этапе необязательна: существующая карточка CV умеет использовать текстовую обложку, позднее можно добавить отдельный скриншот игры.

**Состояние интеграции на 25.11.2026:** репозиторий CV и необходимые файлы определены, структура изучена. Низкоуровневая запись в `SarvasGD/CV` отклонена GitHub-интеграцией с ответом 403; изменения в CV не закоммичены. Нужна однократная настройка доступа GitHub App к репозиторию CV с правом записи Contents. После этого можно внести карточку и iframe-модальное окно одним законченным коммитом.

### 5. Ежедневный процесс после настройки

1. Разработчик меняет канонический HTML и связанные файлы в приватном репозитории.
2. Синхронизирует изменения через GitHub Desktop обычным push.
3. GitHub передаёт событие Cloudflare Pages.
4. Pages собирает и публикует обновлённую версию на том же стабильном URL.
5. Портфолио продолжает показывать актуальную игру через тот же iframe. Переписывать CV или переносить HTML не требуется.

Для крупных изменений можно сначала публиковать preview-ветку и принять её до обновления production.

## Что защищается, а что нет

- Приватный репозиторий закрывает прямой доступ к исходному проекту и его рабочей Git-истории.
- Публичный артефакт содержит только то, что нужно браузеру для запуска игры.
- Минификация убирает форматирование и комментарии, затрудняя беглый просмотр.
- Iframe отделяет игровой адрес от сайта портфолио, но сам по себе не скрывает код игры.
- Невозможно гарантировать, что браузерный HTML/JavaScript нельзя извлечь: пользователь получает и выполняет этот код на своём устройстве. Минификация и обфускация лишь повышают стоимость обычного копирования, но не являются криптографической защитой.
- Для сокрытия алгоритмов от технического анализа потребовалось бы переносить критическую игровую логику на сервер. Для текущей автономной аркады это отдельная архитектура и не является целью Web MVP.

## Одноразовые зависимости и блокеры

1. **Разрешить запись в CV.** Репозиторий `SarvasGD/CV` доступен для чтения, но попытки изменения файлов через текущую GitHub-интеграцию получают 403. Нужно один раз открыть настройки установленного GitHub App, через который подключён GitHub к ChatGPT, и предоставить ему доступ к `SarvasGD/CV` с правом записи Contents. Не требуется давать доступ ко всем репозиториям, если можно выбрать только CV.
2. **Создать приватный репозиторий исходников игры.** Текущие инструменты позволяют работать с уже существующими репозиториями, но не предоставляют действие создания нового репозитория. Его потребуется один раз создать через GitHub UI или GitHub Desktop; после этого исходник и build-скрипт можно перенести туда.
3. **Подключить Cloudflare Pages.** Владелец один раз авторизует Cloudflare GitHub App только для приватного игрового репозитория и создаёт Pages-проект с Git Integration.
4. **Не переписывать прошлую публичную историю без решения владельца.** Текущая версия и Git-история `SarvasGD/Projects` уже содержат исходник игры. Перенос будущей разработки в приватный репозиторий не отменяет того, что ранее опубликованный код можно получить из старой истории.

После этих одноразовых настроек обычное обновление игры должно сводиться к стандартному push в приватный репозиторий. CV не придётся обновлять при каждом релизе.

## Критерии готовности

- Канонический исходник хранится в приватном репозитории.
- Сборка автоматически создаёт публичный HTML-артефакт.
- Успешный push в production branch автоматически обновляет опубликованную игру.
- URL игры остаётся неизменным между релизами.
- CV встраивает игру через iframe, без копии игрового HTML; поле Project Link в RU/EN-контенте задаёт стабильный адрес игры.
- Не публикуются исходники, проектные документы, ключи и служебные файлы.
- Проверено, что браузерная версия работает после минификации.
- Владелец выполняет действия только при первоначальной настройке и приёмке готовой интеграции.
