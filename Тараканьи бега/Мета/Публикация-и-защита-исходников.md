# Публикация и защита исходников Roach Rush

Обновлено: 25.11.2026.  
Назначение: отдельный игровой веб-билд с постоянным публичным адресом и автоматическим обновлением после push. Этот документ относится только к самой игре и её размещению. Портфолио, его код, карточки и iframe не являются задачей этого документа.

## Текущее фактическое состояние

**Не готово. Автоматическая публикация ещё не настроена.**

Проверенное состояние GitHub на 25.11.2026:

- Актуальная игра: `Тараканьи бега/roach-rush.html`, сборка `261125-1643`.
- Исходник находится в публичном репозитории `SarvasGD/Projects`.
- В проекте игры нет `package.json`, `package-lock.json`, build-скрипта и папки `dist/`.
- В `.github/workflows/` нет workflow, отвечающего за сборку/публикацию Roach Rush.
- Cloudflare Pages project не создан или, по крайней мере, не подключён к этому репозиторию и не подтверждён.
- Постоянного внешнего игрового URL нет.
- Автоматический деплой после push не проверен и не работает как настроенная функция проекта.

Следовательно, ни «Cloudflare Pages», ни сборка/минификация, ни публикация пока не являются выполненными работами. Предыдущая формулировка `npm ci && npm run build:game` была примером предполагаемой конфигурации, а не существующей командой проекта. Её нельзя использовать, пока соответствующий package.json и скрипт реально не добавлены.

## Целевой результат

После первоначальной настройки разработка должна выглядеть так:

1. Изменяется канонический исходник игры в приватном репозитории.
2. Обычный push в `main` запускает проверку и сборку.
3. Сборка создаёт отдельный публичный артефакт `dist/index.html`.
4. На отдельном хостинге обновляется один и тот же постоянный игровой URL.
5. Для проверки новой версии не требуется скачивать архивы или вручную переносить HTML на хостинг.

Это самостоятельная поставка браузерной игры. Никаких изменений в CV/портфолио для неё не требуется.

## Рекомендуемая архитектура

```
Приватный репозиторий с исходником игры
                 |
                 | push в main
                 v
        автоматическая сборка
        - проверка JS
        - минификация HTML/CSS/JS
        - подготовка dist/
                 |
                 v
       Cloudflare Pages (Git Integration)
                 |
                 v
       постоянный URL вида *.pages.dev
```

### 1. Приватный источник

Для защиты рабочего исходника будущую разработку нужно вести в приватном GitHub-репозитории. Текущий публичный `SarvasGD/Projects` не должен оставаться единственным источником кода, который предполагается скрыть от прямого просмотра.

**Историческое ограничение:** файл игры уже был опубликован в публичном Projects и попал в его Git-историю. Перенос дальнейшей разработки в приватный репозиторий не удалит прежние публичные версии задним числом. Удалять или переписывать историю Projects без отдельного решения владельца нельзя.

Создание нового репозитория — отдельная одноразовая операция. После его создания туда переносится канонический HTML и необходимые для сборки файлы. Не переносить старую папку `roach-arcade` как источник игры: актуальный файл — корневой `roach-rush.html`.

### 2. Сборка публичного артефакта

В приватном репозитории должен появиться воспроизводимый build pipeline:

- `package.json` и зафиксированный lock-файл зависимостей;
- build script, который берёт канонический `roach-rush.html` и готовит `dist/index.html`;
- проверка синтаксиса всех встроенных JavaScript-блоков до и после минификации;
- минификация HTML, CSS и JavaScript;
- сохранение идентификатора сборки;
- завершение сборки с ненулевым кодом при ошибке.

Обфускацию не включать без отдельного сравнения производительности и регрессионной проверки игры. Минификация — первая ступень, а не гарантия секретности.

**Критерий сборки:** минифицированный артефакт должен пройти проверку и запускаться в браузере так же, как исходная версия. Нельзя считать pipeline готовым только потому, что команда завершилась с кодом 0.

### 3. Хостинг: кандидат Cloudflare Pages

Cloudflare Pages подходит как кандидат для отдельного статического игрового адреса:

- Git Integration подключается к приватному GitHub-репозиторию;
- production branch — `main`;
- build command будет задан после появления проверенного build script;
- build output directory — `dist`;
- после первого успешного deploy сервис выдаёт отдельный URL `*.pages.dev`;
- последующие push в подключённую ветку запускают автоматическую публикацию;
- preview deployments могут использоваться для проверки отдельных изменений.

Официальная документация:
- Git integration: https://developers.cloudflare.com/pages/configuration/git-integration/
- GitHub integration: https://developers.cloudflare.com/pages/configuration/git-integration/github-integration/
- Static HTML: https://developers.cloudflare.com/pages/framework-guides/deploy-anything/

Важно: Git Integration выбирается при создании Pages-проекта. Документация Cloudflare указывает, что переключить Git-integrated project на Direct Upload позднее нельзя. Поэтому способ подключения следует выбрать сразу.

### 4. Что означает «защитить код»

Нужно различать два результата:

**Защита исходного проекта от прямого доступа.** Приватный GitHub-репозиторий закрывает рабочие исходники, документацию и Git-историю будущих версий от публичного просмотра. Отдельный игровой хост отдаёт только собранный артефакт, а не репозиторий.

**Защита браузерного кода от извлечения.** Полностью скрыть HTML/JavaScript, который браузер загружает и исполняет, нельзя. Его можно получить через DevTools или сетевые запросы независимо от того, где он размещён. Минификация и обфускация затрудняют обычное чтение, но не дают абсолютной защиты. Даже WebAssembly не является надёжным способом сделать клиентский код секретным.

Если потребуется скрывать критически важную игровую логику от технического анализа, её придётся выносить на сервер. Это изменит архитектуру автономной игры и не относится к простому этапу публикации Web MVP.

## Что требуется для запуска

Однократные зависимости:

1. Создать приватный репозиторий исходников игры.
2. Перенести туда канонический HTML, сохранив публичный Projects нетронутым до отдельного решения о его истории.
3. Подготовить и проверить build script и lock-файл.
4. Авторизовать Cloudflare GitHub App только для приватного репозитория.
5. Создать Cloudflare Pages project через Git Integration и выполнить первый deploy.
6. Проверить постоянный URL, загрузку игры, ошибки браузера и корректность последующего автоматического деплоя.

До выполнения этих шагов никакого игрового URL нет. Нельзя подставлять в игру или сторонние материалы URL GitHub `blob`/`raw` как замену игровому хостингу.
